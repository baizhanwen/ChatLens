ChatLens Windows 持续采集与停止后恢复验证包

用途与范围
本包沿用你此前成功测试的 selected-config.json 和 selected-keys.json，只持续采集其中同一处私聊和同一处测试群的新文字。
首次建立基线后，这两个会话的新文字正文、发送人和源时间会保存到本机 collector-data/private/store/collector.sqlite3，消息和来源游标在同一事务中提交。该本地 SQLite 未加密，由当前 Windows 用户 SID 的私有目录权限保护。
不要把 collector-data、private、配置、密钥、数据库、联系人列表或聊天截图发到聊天或 GitHub。只有 results 中本轮两个脱敏 JSON 用于回传。
本包无模型、联网、上传、自动发消息、自动提权、内存扫描、服务安装或开机自启功能，不修改微信进程或源库记录。只读 SQLite 的正常锁可能更新源 SHM 元信息。

准备
1. 将 ZIP 完整解压到本机固定磁盘的新目录；不要在压缩包内运行，不使用网络共享、符号链接或联接目录。
2. 保持此前测试的微信 4.1.15.56 登录并联网，电脑开机、屏幕解锁，微信放后台。测试期间不退出或重启微信。
3. 找到此前成功 r2 包那一轮的 results/...-selected-live/private/selected-config.json，旁边应有同一轮 selected-keys.json。两者都含私人配置，只在本机选择。
4. 让同一位测试朋友能够从自己的微信向你私聊、在原测试群发送文字；本工具不替任何人发送。

首次启动
1. 双击 Start-Collector.cmd。只使用 Windows 系统 PowerShell 和包内固定 Python，不安装或使用其他 Python。
2. 在文件选择器中选上面的 selected-config.json。程序会从其同目录读取配对密钥，复核当前用户私有权限、账号目录、固定三库首页与当前同路径同版本微信。旧 PID 不会直接复用。
3. 如果出现多个主窗口候选，按提示选择此前测试的微信编号；无法确认可留空取消。不要选择其他账号来代替。
4. 等明确显示 READY：此时已建立新文字基线，并已开始持续采集，无需再按回车。不要在 READY 前发送本轮测试文字。
5. 控制台会显示本轮四条运行中测试码和两条仅在停机时发送的测试码。测试码只在本机显示，采集仍会保存两个会话的所有新文字，不以这些码筛选正文。

第一阶段：持续接收四条
1. 看到 READY 后，让测试朋友按控制台顺序发送前四条：私聊第一条、群第一条、私聊第二条、群第二条，每条单独发送，各一次，不加其他文字。
2. 让采集继续运行，观察“本次新增”和“本地累计”计数。保持微信后台，不在电脑打开被测会话。计数包含范围内其他新文字，四个码是否通过以本轮 controlled_summary_after 为准。
3. 四条发送完且采集计数更新后，按一次 Ctrl+C，等待程序明确显示已停止和本次 results 路径，再关闭窗口。不要直接关闭终端来代替本轮正常停止步骤。
4. 保留这一轮 results/<时间>-continuous/result-to-send.json 与 supervisor.json。只发送这两个 JSON，不发送 private。

第二阶段：停止期间两条，然后重开补采
1. 确认刚才已停止；电脑和微信继续开着，微信保持登录和后台。
2. 请测试朋友发送先前控制台列出的“仅停机后发送”两条：私聊第三条、群第三条，每条单独发送，各一次。
3. 两条发完后，重新双击同一个解压目录下的 Start-Collector.cmd。不要重新解压替换目录，不移动或删除 collector-data，不改配置或手动重置基线。
4. 本次会自动使用本包 collector-data/private 的配置和检查点，不再要求选择旧包。看到从检查点恢复后，等待停机的两条自动补采；不要重发前四条或这两条编号。
5. 计数更新后按一次 Ctrl+C，等待正常停止。保留本次新 results/<时间>-continuous/result-to-send.json 和 supervisor.json。
6. 将第一阶段和第二阶段各自的 result-to-send.json、supervisor.json 都回传（共四份），可以分两次发送。验收要核对恢复原四条、新增两条、六个编号各一次，不以新增总计数代替样本对照。

日常持续运行与故障
持续模式没有旧测试的五分钟限制；保持本窗口运行即可，正常停止后再开从同一检查点补采。重启不会把基线跳到最新消息。
微信到前台、锁屏或状态无法确认时程序可暂停且不推进游标；后台解锁后再尝试补采。微信进程退出、源库被替换、密钥或分库集合变化、检查点缺失或损坏时会停止并保留已提交数据，不自动切账号或重建基线。
启动器用当前主窗口、程序路径、固定版本和创建时间绑定本次进程；不在运行中自动绑定另一个微信进程。微信关闭后，本工具不能让微信继续接收新消息。
不要同时开启同一 collector-data 的两个采集进程；第二个实例会拒绝，不接管或覆盖已有采集。
本次有独立父进程监督初始化与心跳。空闲没有新消息也会更新安全心跳；正常持续运行没有总时限。按 Ctrl+C 请求自己启动的子进程正常停止；若卡住则有限等待后终止本工具子进程，不关闭微信。已提交消息和游标可在下一次重开恢复。
如果控制台文字被鼠标选中高亮，先按 Esc 取消选择再观察，避免终端选择状态影响输出。
故障只反馈控制台固定 reason 或本次脱敏 JSON；不要粘贴本机完整路径、私有 JSON 内容或密钥。

依赖与证据边界
固定便携依赖：Python 3.14.10 官方 Windows x64 embeddable、sqlcipher3 0.6.4 普通 cp314 x64 wheel、zstandard 0.25.0 cp314 x64 wheel。来源 URL、固定 SHA256 和逐文件摘要在 COLLECTOR-MANIFEST.json；python314._pth 仅添加 ..，site 关闭。不安装 pip 或修改全局环境。 目标本地存储另使用该官方 Python 已捆绑的标准库 sqlite3、_sqlite3.pyd 和 sqlite3.dll；不新增系统安装。
许可证保留在 THIRD-PARTY-SELECTED-NOTICES.txt、runtime/LICENSE.txt 和 runtime 内对应 dist-info/licenses。
此前 r2 两轮四条受控后台读取已有用户实机报告；本包是新的持续采集和恢复实现，打包或本机合成测试不等于本包 Windows 恢复已经通过。真实持续运行、两阶段停机补采、最小化、锁屏、长期稳定性和其他微信版本分别验收。
结果中的正常停止 status=通过只表示本次程序退出且检查点可读；停机补采必须另对两轮受控摘要、恢复计数和源时间。没有每条完整端到端计时口径，不声明严格实时延迟。
