# ChatLens 本机 Web 工作台

> 当前 Windows 升级测试包为 `ChatLens-Windows-Web-20261101-r2.zip`，支持多会话关注和收到／发出／未知统计，复用原数据目录。请优先按 [Windows 新版测试包](Windows新版测试包.md) 操作；本文保留首版两会话 Web 交付及其当时验收边界。

本轮将此前验证过的两会话持续采集接到网页，展示原选定私聊、群聊、已保存文字、采集状态和后续新消息。页面保留「利明智耀」标识与已确认的暖白、鼠尾草绿界面。

这是本机单用户服务。网页仅监听 `127.0.0.1`，不会开放局域网、上传聊天、调用云端模型或自动发送微信消息。本轮没有新增会话选择、AI 分析或手机通知。

## Windows 启动

交付包为 `artifacts/deliverables/windows-check/ChatLens-Windows-Web-20261101.zip`，完整解压到本机固定磁盘的新文件夹后，双击 `Start-ChatLens.cmd`。

包内已携带固定版本的 Python 与读取依赖，无需安装 Python、Node、Codex 或 pip，不注册系统服务或开机自启，也不改变全局环境。保留整个解压目录，避免单独移动入口文件。

1. 如果旧持续采集窗口仍在运行，先在旧窗口按一次 `Ctrl+C`，等待正常退出。
2. 在新入口的目录选择器中，选此前持续采集包中的整个 `collector-data` 文件夹。旧包名称为 `ChatLens-Windows-Collector-20261101`；所选目录下应保留原来的 `private` 子目录及所有文件。
3. 选择的是 `collector-data`，不是 `private`、`selected-config.json` 或新的空目录。无需把原数据复制到新包。
4. 继续采集时，保持此前测试的 Windows 微信 `4.1.15.56` 登录、联网、处于后台且屏幕解锁。启动器按原程序路径、已测版本、主窗口与当前进程创建时间核对；多个候选需在本机选定。
5. 等待浏览器自动打开本机页面。控制台显示本机地址；默认浏览器未能打开时，按控制台提示在本机粘贴完整登录地址。

真实入口使用启动器提供的本机 HTTP 地址。直接打开 `web/index.html` 的 `file://` 模式仍是明确标注的虚构界面预览，不连接真实数据。真实连接失败不会切换成虚构联系人或示例消息。

完整登录地址只用于当前本机浏览器，含本次会话凭据，不要转发、提交或放入截图。程序使用浏览器内存与本机 HttpOnly 会话 Cookie；公开诊断不包含登录地址。

## 网页展示

- **沟通总览**：两会话的消息数量、最近文字与当前采集状态。
- **会话消息**：原选定会话及已提交文字，可切换会话、查看更早消息；阅读旧内容时，新消息使用提示，不强制跳到最新。
- **采集状态**：真实心跳、累计数量、是否从持久检查点恢复及明确的等待、停止或错误说明。浏览器打开不代表采集已经运行。

联系人名称只通过原选定会话和已观察到的发送人作精确元信息查询，不扫描其他会话正文。元信息尚未准备好时，使用“所选私聊”“所选群聊”“未知发送人”等保守说明，不根据示例或正文猜测名称。

网页读取本机采集库中已提交的消息，不参与源库写入，不抢占采集单实例锁。页面没有自动发消息、重设基线、切换账号或扩大采集范围的操作。

## 微信不在线时

未找到原路径、已测版本的微信主窗口时，启动器说明“本次仅展示已保存消息”，以只读模式打开已有数据。

这条路径不启动采集、不读取解密密钥、不打开微信源数据库。启动微信并完成登录后，关闭本次入口，再重开并选择同一个 `collector-data`，即可重新核对采集条件。

状态依据私有心跳显示：心跳缺失时显示不可用；运行阶段心跳过期时显示状态过期。源微信退出、采集失败或网络断开时，已保存内容可保留展示，同时明确说明状态。不要通过删除锁、配置或数据库来尝试恢复。

## 停止与恢复

在本次入口的控制台按一次 `Ctrl+C`，等待正常结束。入口只请求停止本轮启动的采集及网页服务，不关闭微信，不结束其他采集进程，不抢占旧锁。

下一次从同一入口选择同一个 `collector-data`，会继续使用原消息库与持久检查点，不复制旧数据、不重建基线、不跳过停机期间已经到达微信本地数据库的消息。原账号、源库身份、分库集合或检查点不匹配时，保留数据并报告原因。

电脑关机后，本工具不能替微信继续接收消息。页面只能展示已经保存在本机的内容。

## 数据与反馈

真实文字保存在 `collector-data/private/store/collector.sqlite3`。它是本机权限保护的普通 SQLite，**未加密**。配置、解密密钥、检查点及名称元信息也只留在原本机受保护目录；新包不包含这些资料。

一次运行的公开诊断位于新包的 `results/<本次时间>-web/`。需要反馈时，仅提供其中生成的公开 `result-to-send.json`，以及按具体故障说明要求的采集公开报告。不得发送 `collector-data`、`private`、配置、密钥、数据库、完整登录地址或包含真实聊天的截图。

本轮公开 JSON 记录进程生命周期、状态与数量，不含真实正文、联系人名称、账号标识、私人路径或会话登录凭据。“本机服务正常退出”与“真实新消息展示通过”分别判断。

## 实机核对与边界

此前 Windows `4.1.15.56` 的两个会话六条受控文字与一次正常停止恢复已有独立实机证据，见[持续采集与恢复](持续采集与恢复.md)。新 Web 连接需要独立核对，不能由旧采集结果或静态页面检查替代。

| 验收项 | 状态 | 核对方式 |
| --- | --- | --- |
| 原 Windows 两会话采集与一次正常停止恢复 | 通过 | 已有独立六条受控实机证据，限原电脑与版本 |
| 新 Web 包在 Windows 启动并显示原已保存消息 | 未验证 | 运行新入口，核对原会话及已保存消息，不显示虚构示例 |
| 新 Web 页面显示运行中收到的真实文字 | 未验证 | 受控朋友从原私聊、原群各发一条，核对正文、发送人、归属与增量数量 |
| 新 Web 包正常停止后恢复且无重复 | 未验证 | 正常停止、重开同一数据目录，核对保存内容与新增消息 |
| 其他电脑、其他微信版本、锁屏、最小化、长期稳定性 | 未验证 | 需单独受控实机验收 |
| macOS 新持续采集与 Web 启动器 | 未验证 | 本轮启动器面向已实测 Windows；历史 Mac 受控读取不等同新 Web 接入 |

新页面验收时还应在阅读旧内容的位置接收新文字，核对新消息提示及返回最新；断开或停止采集后检查状态提示。自动化与合成联调只验证实现契约，不代表真实微信已接入。

## 固定依赖

本包使用 Python `3.14.10` 官方 Windows x64 embeddable、`sqlcipher3==0.6.4` cp314 Windows x64、`zstandard==0.25.0` cp314 Windows x64。目标采集消息库使用官方 Python 已附带的标准库 `sqlite3`、`_sqlite3.pyd` 与 `sqlite3.dll`，系统权限和进程检查使用 Windows API。

原文件来源、固定摘要与逐文件大小及 SHA256 记录在 `WEB-MANIFEST.json`，Python 与第三方许可随包保留。打包仅使用已审查的固定本机缓存和公开源码白名单；构建期间不读取真实聊天、不下载或全局安装软件。
