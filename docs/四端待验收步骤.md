# 四端发布待验收

本轮M0–M5开发版已交付对应系统的接口与构建入口；以下为M6待办，不填写虚假通过状态。

| 端 | 本轮证据 | 待验收 |
|---|---|---|
| macOS微信 | 运行版本4.1.11，元信息探针，辅助功能权限受限 | ≥100条受控真实消息、真实本地视觉模型、可见原始时间、重复文本、窗口变化与缺口、权限撤销恢复、真实停靠 |
| macOS QQ | 运行版本7.0.2，其余同上 | 独立进行≥100条受控对照，不复用微信读取结论 |
| Windows微信 | UIA探针、PrintWindow裁剪、SetWindowPos停靠、NSIS构建脚本 | Windows真实构建、安装、启动、权限、≥100条对照；关注变化与云端视觉门控当前不支持 |
| Windows QQ | 独立客户端接口与脚本 | 独立执行Windows全流程；不能用Windows微信结果替代 |

每次记录：硬件、OS build、客户端准确路径和版本、Chatlens构建hash、视觉模型型号/运行方式、权限状态、采集模式、裁剪范围、测试起止时间、对照原始数据位置、预期条数、取得条数、漏采/重复/文本错误、失败例与证据路径。真实个人原文仅留本机私密目录，不公开提交。

执行顺序：

1. 对应系统构建并安装：macOS `sh scripts/build-macos.sh`；Windows `powershell -File scripts/build-windows.ps1`。记录失败日志，验证安装和卸载。macOS目前仅arm64本机构建，Intel须对应运行时和原生helper重新构建，不移用arm64结论。
2. 运行元信息探针，手动授予用户同意的屏幕录制/辅助功能权限。验证撤销时清晰暂停。辅助功能用于窗口状态和停靠，消息主读取仍视觉。
3. 用受控账号与会话准备100条以上消息，包含相同文本不同发送、乱序可见时间、引用、媒体占位、快速连续发送和会话切换。先建立逐条预期，再实测，不能用应用自身输出充当原始对照。
4. 先用本地视觉模型，确认裁剪预览和标题核对；云端另行明确授权。macOS云端标题门控需真实布局验收；Windows本版拒绝云端视觉。
5. 分别测试前台、遮挡、后台、最小化、滚动、锁屏、切会话、客户端重启、应用重启、模型断线、权限撤销。验证状态、持久游标与缺口，标为受限的场景不得填写完整采集通过。
6. 在无需滚动而对方持续发消息时验证关注模式。记录实际变化事件、触发、防抖、最长等待、模型请求时间及可见重叠；若刷屏缺失，记录缺口和失败例，不把0误填为漏采率。
7. 统计真实取得消息至UI展示p95、窗口合并结束至分析展示p95，分别列出截图/本地标题门控/VLM/规则或文本模型耗时；不能把现有API→DOM合成性能当真实采集性能。
8. 逐项验证原文引用、事实/推测标识、未知时间/身份、任务修正、确认与提醒、导出范围、原文撤回失效、模型中断时检索、退出恢复、数据删除及checkpoint清理。
9. 长时间稳定性与重启恢复需真实运行记录，四端分别签收。未完成时compatibility.json保持未验证或受限，发布状态保持待验收。
