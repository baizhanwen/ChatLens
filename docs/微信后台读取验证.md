# 微信后台读取专项验证

日期：2026-10-26（Asia/Shanghai）。范围：电脑开机、联网、微信登录时，读取指定会话在启用后收到的新文字消息。本轮不建设 Web 页面，不调用模型，不替用户发送消息。

**最小本机测试结果：通过。** 17:38 从手机发送到文件传输助手的两条唯一测试文字，均在 Mac 微信非前台且隐藏时从原版微信数据库读取，正文完全匹配，各出现一次。此结论仅覆盖本机 macOS／微信 4.1.11 的该受控单会话测试。

## 验证入口

```bash
python3 scripts/probe_wechat_database.py --output artifacts/verification/wechat-background/2026-10-26/preflight-after-permission.json
python3 scripts/probe_clients.py --platform wechat --output artifacts/verification/wechat-background/2026-10-26/window-preflight.json
```

`scripts/prepare_wechat_read_test.py` 是本任务编写的窄化辅助程序：只准备私有副本、启动自己的测试子进程、筛选与所选消息库盐值相符且通过首页 HMAC 验证的密钥。它不会附加既有微信进程、修改原版、关闭 SIP、索取或保存管理员密码、导出聊天或发送消息。`capture` 阶段要求原版已由用户正常退出，并在结束后请求恢复原版。副本仍访问同一账号的本地数据，不等于隔离测试账号。

取钥方法参考经过只读审查的 [MIT 临时副本实现](https://gist.github.com/acmerfight/0a01249ef72970d07a2603dbb629e80f)；没有执行其下载脚本。现成 [wx-cli](https://github.com/r266-tech/wx-cli) 的默认 macOS bootstrap 涉及管理员凭据存储取舍，本轮没有运行该初始化或安装其全局组件。

只读查询准备使用隔离目录 `.build/wechat-read-venv`（Python 3.12.14），临时测试依赖 `sqlcipher3-wheels==0.5.7`、`zstandard==0.25.0`，仅安装二进制 wheel，不改全局环境或应用依赖。

`scripts/watch_wechat_test_messages.py` 只对固定 `filehelper` 表建立各正文分库的 `MAX(local_id)` 基线，随后以 `mode=ro`、`query_only=ON` 查询新文字；不开启会忽略 WAL 的 `immutable` 模式。未匹配测试编号的内容不输出、不保存。SQL 写入被拒绝；SQLite 的 WAL 共享内存读锁元信息可能更新，不将这种模式宣称为整个源目录逐字节不变。

该 watcher 的 5 项独立合成 SQLCipher 测试通过，覆盖未 checkpoint 的 WAL、新旧消息与其他会话过滤、分页、写入拒绝、压缩正文和双份后台状态判断；合成测试不能代替上述两条真实微信证据。

## 最小成功标准

1. 在文件传输助手建立基线后，由用户从手机发送本轮生成的唯一测试文字。
2. 读取时 Mac 微信确实处于非前台；取得完整正文和稳定消息标识。文件变动、未读数、会话事件、旧消息或 OCR 均不能替代这一证据。
3. 公共报告仅记测试消息匹配结果、计数、时间和前后台元信息；私人正文、密钥和账号标识不进入公共证据。
4. 文件传输助手通过只证明单会话跨端同步的后台读取可行。客户来信、群聊、多会话同时来信、最小化、断点补采及长期完整性仍需分别验证。
