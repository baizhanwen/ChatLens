# 视觉读取与触发策略

主路线为指定聊天窗口截图→可替换视觉模型→结构校验→重叠匹配→事务入库。AX/UIA仅辅助窗口状态或作为独立降级；OCR结果不标为视觉模型结果。无模型时导入、检索、规则分析继续可用。

普通模式：启动后由用户操作触发一次，之后只响应手动读取和前台切回事件；周期截图默认关闭。未实现的原生内容变化、滚动和输入状态事件不能展示为已支持。

关注模式：显式启用后，通过本机指定窗口ROI变化检测发现无滚动的新消息。感知画面变化属于持续本地观察，不能声称完全不读取画面；它与持续调用视觉模型不同。帧只在内存本地做变化计算，不逐帧发送模型。截图识别仅在变化触发后执行。只监测所选窗口，非前台、锁屏及窗口不可见时暂停并显示缺口。

调度步骤：等待事件→防抖合并→最长等待截止→冷却检查→截图→哈希比较→变化时调用模型→校验→原子入库。识别过程中再次变化保留待处理事件。连续消息不能使防抖永远等不到稳定；调度有最长等待。整体任务串行，限制模型超时与重试，失败3次暂停等待处理。

图像哈希无法理解语义，光标、动画、时间栏会造成误触发；ROI尽量覆盖聊天内容、排除标题和输入框，但准确区域仍需对应客户端版本实测。置信度为模型自报值，未经校准，不作为已验证准确率。

第一次读取建立可见基线。后续读取通过发送人、可见原时间、类型、内容及出现顺序匹配重叠；同文本不同出现保留。没有重叠时标记可能缺口。纯视觉无法证明屏幕外、后台或高速刷屏没有漏消息；即使有重叠也不能保证不存在中间快速移出的内容。不得自动滚动或发送消息。

没有可读原始时间时使用取得时间作为排序占位，同时保存 `metadata.original_timestamp=null`、`timestamp_quality=observed_only_not_original`；不据此解析“明天”的截止日期或计算回复时长。

云端截图可能包含聊天原文。必须先选择模式、模型及绑定会话，确认外发范围；凭据只从进程环境取得。默认禁用云端，临时截图处理后删除，数据库为普通未加密SQLite。截图不进入日志、公开仓库或报告。

验收分层：调度单测；合成窗口原生变化监测试验；假视觉模型协议试验；真实视觉模型质量；真实微信/QQ 100条受控消息对照。前3项不能代替后2项。
