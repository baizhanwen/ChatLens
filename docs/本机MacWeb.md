# ChatLens 本机 Mac Web 工作台

> 本页主要记录源码目录的本机入口。GitHub 独立下载包及其固定用户资料目录、系统条件和校验方法，见[macOS 下载测试指南](macOS下载测试指南.md)。两种入口分别保存资料，不自动搬移开发版私人目录。

Mac 微信数据库读取连接到「利明智耀」Web 界面。启动时自动识别当前微信，首次在本机初始化，再在网页选择1–50个私聊或群聊；只采集所选范围启用后的新文字。网页仅监听 `127.0.0.1`，本机统计不调用模型，模型分析须主动确认范围，不代发微信消息。原两会话数据和历史验收保留；新版范围隔离及收发身份见[收发身份与多会话](收发身份与多会话.md)。

## 启动入口

在项目根目录双击 `Start-ChatLens.command`。入口检查项目已有的隔离 Python 与 `macos-probe-web` 状态探针，再启动 `scripts/macos_web.py`；不会安装 Homebrew、Python、Node、Codex 或系统服务，也不会修改原版微信。

启动后，默认浏览器打开本机工作台。保留终端窗口，正常停止时按一次 `Ctrl+C`，等待退出；不要强制结束微信或删除本地检查点。

缺少隔离运行环境、状态探针或公开启动脚本时，入口显示固定原因并退出，不自动改用电脑上的其他 Python，也不自动编译。当前入口面向这台已准备环境的 Mac；另一台 Mac 的安装、签名、权限及真实采集需要独立验收。

## 本机配置与范围

1. 保持需要使用的微信正常登录。程序通过唯一微信主进程及其已打开文件的元信息识别当前账号，不让用户查找旧配置或数据库路径，也不依据磁盘上的旧账号文件夹猜测当前账号。
2. 首次使用当前账号时，按本机初始化提示操作。需要短暂退出时，先保存草稿，再从微信菜单正常退出；临时初始化副本要求登录时，在本机点击进入微信或用手机确认。不要在聊天里发送密码、验证码或密钥。
3. 初始化只为当前账号取得读取所需的本机能力，不修改原版微信。完成后按提示恢复原版登录，再在网页选择关注的私聊和群聊。
4. 开始采集后，仅保存本次选定会话的新文字。存在多个无法唯一确认的主进程或活动账号时，程序明确停止，不自动选第一个账号。

新 Mac Web 使用独立的 `artifacts/private/macos-web/` 私有目录，不覆盖旧受控测试的配置、密钥、检查点或证据。所有配置在本机由初始化与网页选择产生，不需要手工准备 `bootstrap.json`、选择旧配置路径或上传任何私有文件。

旧 Mac 受控测试只保存测试编号匹配摘要，未保存普通聊天正文，不能直接作为新工作台的消息库。新数据目录首次建立当前基线，从启用后收到的新文字开始保存；后续重开沿用已提交的消息与持久检查点，不重建基线。

选择页通过会话表名和联系人名称元数据列出可选会话，选择前不读取聊天正文。选定后，工作台展示所选会话与当前状态；发送人名称仅作精确联系人查询，无法确认时使用保守名称，不通过其他会话正文猜测。真实服务失败时显示实际原因，不切换成虚构示例。

直接打开 `apps/web/index.html` 的 `file://` 模式仍是明确标注的虚构界面预览。真实工作台必须从启动器提供的本机 HTTP 地址进入。

## macOS 权限

本机运行环境：隔离 Python 3.12.14、`sqlcipher3-wheels==0.5.7`、`zstandard==0.25.0`；状态探针由 Apple Swift 编译。首次初始化需要 Apple 系统 Python 3.9.6 与 Xcode 提供的 LLDB 模块、系统 `ditto`／`codesign`。源码中的 `scripts/build_native_macos.sh` 编译旧组件，新 Web 探针需由同一 `scripts/native/macos_probe.swift` 编译为 `scripts/native/bin/macos-probe-web` 后本机签名；入口缺文件时不会偷偷编译或安装。这些条件已在本机核对，另一台 Mac 仍需独立准备与验收。

微信数据库位于受系统保护的容器目录。此前授予 Codex 或 ChatGPT 的“完全磁盘访问权限”，不自动证明双击入口所用的 Terminal 也能读取。

若入口报告源库权限不足，应按系统设置为实际承载本次入口的终端应用授予“完全磁盘访问权限”；系统要求重启该应用时，重启后再运行入口。不要更改 SIP，不使用管理员权限扩大文件读取范围，也不要把私有文件改成所有人可读。

数据库文字采集不依赖录屏或 OCR；本轮不会要求读取屏幕聊天内容。原生探针只提供微信运行、前后台与锁屏等状态元信息，不使用 `--capture`。

## 运行与停止

继续采集时，保持已确认版本的微信登录、联网、处于后台且屏幕解锁。前后台与锁屏条件在每次读取前后检查；条件不满足时保留游标并暂停，不把尚未提交的数据当成已采集。

网页的会话、消息数量和采集状态来自本机已提交数据与真实心跳。网页能打开不代表微信正在采集；缺少或过期的心跳必须显示不可用或过期。

按一次 `Ctrl+C` 正常停止后，下次双击同一入口会复用当前账号、当前关注范围的目录。停机期间已到达微信本地数据库的所选会话文字可在恢复后补采。识别到另一个有效微信账号时，先停旧采集与 AI、清空旧页面域，再加载新账号自己的配置；不复制旧账号密钥或套用旧检查点。源库身份、密钥、分库集合或检查点异常时保留数据并说明原因，不重置。

电脑关机后，本工具不能替微信继续接收消息。Mac Web、Windows Web 与两端各自的私有数据分开，不通过本项目自动同步聊天。

## 数据与反馈

每个账号使用单独的 `artifacts/private/macos-web/accounts/<本机账号摘要>/` 目录；新消息库位于其中的 `collector-data/private/store/collector.sqlite3`，它是普通 SQLite，**未加密**。原始账号路径不会放到网页或公开报告。真实正文、联系人名称、账号标识、配置、密钥和检查点只留本机，不进入 Git 或交付包。

本机网页使用本次会话凭据。完整登录地址、会话 Cookie 与令牌不要转发、提交或放入截图。诊断反馈只提供明确生成的公开 JSON；不要发送 `artifacts/private`、配置、密钥、数据库或真实聊天截图。

源库按正常 SQLite 只读连接读取，不写源数据库记录、不主动 checkpoint。正常 WAL 读取可能更新 SHM 锁元信息，不承诺全部源文件字节零变化。
