# 收发身份与多个关注会话

工作台使用本机已采消息的稳定发送者 ID 区分收到、发出和方向未知。多个关注会话需要在本机选择页明确勾选，不会自动关注全部微信会话。

## 本人身份怎么确认

本人候选来自已核对的当前活动账号目录，并与联系人库的精确 username 唯一匹配。目录名和昵称都只提供候选，不能单独作为本人依据。

程序再核对已经选择的一对一正常文字会话：对方 ID 之外的唯一发送者必须与账号候选一致。核对使用逐分片 Name2Id 解析后的稳定 ID，不依赖 rowid 为1、2等固定位置。新采记录尚未含本人发言时，可以只查询所选私聊的发送者 ID 元数据；不会读取、导入或分析历史聊天正文，也不会增加旧消息记录。

核验结果绑定当前账号和消息库。本人消息标为发出，其他已识别发送者标为收到，发送者缺失或身份不可验证时仍为未知。昵称恰好叫“我”的联系人不会因此被当成本人。无法核验时，相关查询会说明限制，不把全部记录当作收到。

同一账号切到另一个关注范围时，可以复用已验证的身份依据，但会再次核对账号上下文和精确候选，重新绑定新消息库。其他账号不能沿用这份身份依据。本人 ID 和证明只留在本机私有元数据中，不进入浏览器接口或模型请求。

首次只选群聊、又没有已核验的同账号身份依据时，方向可能暂时未知。可以由用户明确选择一个普通私聊取得核验依据，再切回原范围；程序不会为此自动关注其他会话。

## 收到与发出怎么问

- “今天谁给我发消息了”：只统计收到的消息和发送者，排除本人及方向未知的记录。
- “今天我发了几条消息”：只统计本人发出。
- “今天收到和发出分别多少条”：分为收到、发出、未知三个桶，合计等于匹配消息总数。
- “我给哪些会话发过消息”：按会话对象分组，不把本人当作收件人，也不把群成员数当作收件人数。

原消息和 AI 引用上下文使用同一套方向判定。消息页将本人发言排在右侧，并明确标注未知方向。分析检索也遵守相应的方向过滤。

## 多个关注会话

在 Mac 或 Windows r3 本机连接页点击“修改关注范围”，加载可选联系人和群名称，再勾选需要关注的会话。可以选择1至50个私聊或群聊，同类会话也可多选。加载名称本身不停止当前采集；确认新范围后才开始切换。

2026-11-02起，同账号修改关注名单时，仍在新名单中的会话继承已采文字；新范围首次建立时，该交集会话继续使用切换前最后提交的逐分库游标，新加入会话才建立本次启用基线。已创建的范围可补入该账号原先已保存的相同会话文字，保留目标现有消息ID、采集位置与AI引用；没有前驱记录时不猜测过去未采到的时间段，也不倒退检查点补读。已移除会话不进入当前名单，原范围的数据和AI对话保留，可显式切回查看。不同范围的AI历史不自动复制。

同账号的新范围可沿用首次模型配置，后续配置及对话仍按范围保存；不会把模型密钥或对话复制给另一个账号。切换范围时会关闭旧采集器和 AI 服务，并清理页面缓存。旧页面的请求标记立即失效，不能用旧请求、旧引用或旧 AI 对话访问新范围，即使两个范围中存在相同会话。

每个会话有独立的基线、游标及消息唯一标识。总读取预算受会话数和分片数共同限制，停机恢复不会把一个会话的位置套用到另一个会话。采集写入及只读接口都会检查当前绑定的允许范围，格式有效但未选择的会话也不能读取。

## 运行与验收边界

多选管理入口已接入 Mac 和 Windows r3 运行时。Windows 新包复用旧 `collector-data`，新增范围保存在原目录的 `private/profiles`，旧的消息、模型设置及检查点原位保留；新包不为其他账号自动初始化密钥，选择范围限已有验证密钥覆盖的消息分片。Windows 主进程和子采集器会核对指定进程已打开数据库的账号路径元信息；证据不足或出现其他账号时停止源读取，不能猜测为原账号。显式只读入口不探源或扩大范围；正常连接模式可以在浏览旧消息时继续检测微信，首次未点击开始前不采集新正文。原生账号探测、权限和运行表现仍须 Windows 实测；详见 [Windows 新版测试包](Windows新版测试包.md)。历史 Windows ZIP 保留原样。

验证必须分别记录：合成身份及方向、多个会话持续／恢复、账号／范围／旧请求隔离、桌面及390px交互、本机实际身份与当前已采记录。自动化只使用合成数据和受限制的本机模型，不代替用户发送微信消息，也不擅自勾选新的真实会话。

2026-11-01 本机只读核对：原有两个关注会话和四条已采文字保持不变，身份核验后分为收到三条、本人发出一条、未知零条；消息页与本机统计一致。新版多选入口能加载当前可读名称并保留原勾选，尚未替用户确认新的真实范围。新的本人发言到达与新增真实多会话采集，仍需单独实测。完整证据与限制见 [验收报告](验收报告.md)。
