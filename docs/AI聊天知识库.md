# AI 聊天与聊天知识库

ChatLens 的 AI 首页帮助你从已采集的微信文字里找重点、回看约定、整理待跟进事项。可以直接问“今天有哪些事情需要我处理”“这个客户最近约定了什么”“群里有没有交付延期的消息”，再点回答中的引用核对原话。

先完成本机微信接入和会话选择，确认消息已经保存。AI 使用的是这些已采文字，不会因为提问而扩大采集范围、读取全部微信历史、自动回复客户或执行聊天里的指令。

## 第一次配置 MiniMax

人数、条数、活跃排行等统计问题可直接提问，不需要先配置模型。页面会标记“本机统计”并显示实际日期；总结、跟进及业务判断才需要下面的模型配置。查询例子、结构化追问及数据边界见[查询分流与统计](查询分流与统计.md)。

1. 从本机启动器打开真实 HTTP 工作台，从侧栏进入“设置”，找到模型配置区域。
2. 选择 MiniMax 国内或国际服务，核对 API 地址与模型。在这台电脑的设置框填写自己的 API Key，不要把密钥发到聊天或放进截图。
3. 点击“保存到本机”。保存只更新本机配置，不测试网络，也不发送聊天。
4. 主动点击“测试已保存配置”。这会向已保存的服务发送一次固定短测试问题，不带微信文字、检索证据或历史提问。测试与正式提问分别判断。

当前国内预设 Base URL 为 `https://api.minimax.cn/v1`，国际预设为 `https://api.minimax.io/v1`；官方当前 Chat Completions 文档列出的模型为 `MiniMax-M3.1-Flash` 和 `MiniMax-M3`。地址填写 Base URL，后面不再追加 `/chat/completions`。[MiniMax 国内官方 API 文档](https://platform.minimax.cn/docs/api-reference/text-chat-openai)、[MiniMax 国际官方 API 文档](https://platform.minimax.io/docs/api-reference/text-chat-openai)

默认配置为空，预设不会自动调用服务。自定义兼容服务必须使用 HTTPS；明确的本机回环 HTTP 地址也可使用。远端服务需要用户在本机配置密钥，程序不借用其他项目的凭据，不自动换域名或跟随 API 重定向。

同一 API 地址下，密钥输入框留空表示保留现有密钥，输入新值表示替换；勾选删除表示移除。只切换同一服务的模型可保留密钥，更换 API 地址则会清除旧密钥，需为新地址重新填写。切换模型或更换密钥都会更新目标指纹；网页只显示是否已保存密钥，不显示密钥内容或末尾字符。

保存或离开设置页会清空本次密钥输入，不回填已保存的原值。离页本身不删除本机已经保存的密钥，也不会自动保存、测试连接或发送聊天；删除需要明确选择并保存。

## 提问与发送范围

先选会话，再选“今天”“最近 7 天”或“全部已采文字”，最后输入问题。这里的“全部”指本机知识库中已经采集并保存的文字，不是微信全部历史。

使用远端模型前，核对页面显示的 API 地址、模型和本轮文字范围。按本人 2026-11-02 的设置要求，“允许发送相关文字片段”默认勾选；更改会话、时间范围或模型目标后，对新的可见范围与目标恢复默认勾选。本人手动取消后，当前范围内的状态轮询和草稿刷新不会重新勾选，模型问题会在发送前被阻止。只有本人点击发送才提交问题，页面不会在后台自动分析聊天；后端仍核对本轮范围及目标指纹。

每次提问先在本机检索，再发送受数量与长度限制的相关片段。请求包含你的问题、必要的会话／发送人名称和时间、原文片段及引用编号；同一范围对话中，也可能携带最近的少量用户提问帮助理解追问。请求不会附带微信数据库文件、采集解密密钥或本机内部定位字段，也不自动发送整套聊天历史。

换会话或时间范围会开始新的 AI 对话，原对话仍可在历史中查看。继续追问时，应留意当前范围，避免把“已付款了吗”这样的疑问误当成聊天中已经确认的事实。

## 知识库、引用与原消息

本项目的“聊天知识库”是对本机已采文字作检索和引用，**不是训练或微调模型**，也不是把所有微信资料上传成远端知识库。

回答中的 `[E1]` 等编号对应本轮实际提供的片段。点击引用或证据卡，可进入消息页并定位本机保存的原话与同会话附近内容；这些来源仍限于已采消息，不会因此去微信补读过去全部历史。

引用能帮助核对来源，不等于模型的每项解释都已经得到事实确认。涉及客户承诺、订单、付款、退款、交付时间或需要拍板的结论，应点开原话确认语境。建议与推测应和对方已经明确表达的事实区分开。

知识库会显示启用起点、已采数量与最近保存时间。检索可能只覆盖相关候选的一部分；页面出现“只覆盖部分相关片段”等提示时，不能据此判断其他消息不存在或遗漏为零。原始发送时间不可用时，会说明采用采集时间，不能把采集时刻当成对方发言时刻。

## 空白、错误与取消

- **还没有已采文字**：先等待选定会话的新文字保存，再提问；配置模型不会补出旧聊天。
- **本次没有相关证据**：返回本机的证据不足说明，不调用模型编成一段分析。可以调整会话或时间范围后再问。
- **正在检索／生成**：显示真实阶段；连接暂时中断时，不把任务当成已经完成，也不换成虚构示例。
- **认证、网络、超时或引用错误**：显示固定原因，保留原消息。模型调用有 45 秒网络预算，不会无限自动重试；需要时由用户检查设置后重试。
- **对话记录较长**：在调用模型前核对本机历史文件的可保存预算；不足时提示开始新对话，本轮不调用模型，旧对话保留。
- **取消**：中止本轮等待与自己的网络连接，取消后的晚到回答不会作为成功答案保存。已经发送到所选服务的内容仍已到达该服务，取消不能将其撤回。上一项操作尚未结束时，应等待页面解除忙碌状态。

不要为了排错删除原消息库或检查点。重开工作台仍使用本机已保存的数据；采集停止后，已采内容仍可用于本机查看和检索。

## 本机保存与隐私

模型配置保存为账号私有目录下的 `provider.json`。Mac 文件权限为 `0600`，目录权限为 `0700`；Windows 源码使用当前用户的私有 ACL。AI 历史保存在同目录的 `threads/`，包含提问、回答及引用片段；这些文件采用权限保护，**未加密**。原采集消息库同样是权限保护的普通 SQLite。

Mac 原关注范围使用 `artifacts/private/macos-web/accounts/<本机账号摘要>/assistant/`，新关注范围使用该账号下的 `profiles/<范围摘要>/assistant/`，各自独立保存对话；同账号新范围首次可沿用模型配置，其他账号不复制。Windows 源码接入仍使用所选 `collector-data/private/assistant/`。AI 读取原采集库时不重建基线、不改消息或游标、不取得采集写锁。范围切换与收发身份见[收发身份与多会话](收发身份与多会话.md)。

不要把这些私有目录、API Key、数据库、完整本机登录地址或真实聊天截图上传 GitHub、反馈到聊天或交给第三方。公开报告只记录明确脱敏的状态与计数。网页设置不把 API Key 写入浏览器本地存储，模型错误也不会直接展示上游原始响应。

## 运行与验证边界

Mac 的真实入口、初始化与权限见[本机 Mac Web 指南](本机MacWeb.md)。直接打开 `apps/web/index.html` 的 `file://` 模式只展示明确标注的虚构预览，不保存真实模型配置，不连接模型。

现有 Windows Web ZIP 保留原样，**其中没有本轮 AI 功能**。Windows 源码已加入 AI 接口与本机消息库连接，本轮没有重打新的 Windows 交付包；不能把旧 ZIP 当作 AI 版本，也不能用源码或合成测试替代 Windows 实机验收。

2026-11-01，本机用户已在网页配置MiniMax并确认连接测试成功，随后确认所选片段范围提交问题，实际生成一轮回答。回答的4个引用均与本机保存的原消息一致，用户确认可跳转；知识库为2个会话、4条已采文字。此结果不代表其他客户环境、所有推理结论或长期完整性均已验证。

其他用户仍须先在网页本机配置自己的 Key，并主动测试。测试未完成前，不把“页面可打开”“设置已保存”或合成模型响应记作真实连接成功；选定片段的问答与引用也分别核对。
