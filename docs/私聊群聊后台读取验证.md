## 验证协议

第一阶段建立每个选定会话、每个正文分库的 `MAX(local_id)` 起点。用户确认微信正常登录并切回其他应用，由受控发送人在私聊和测试群交替发送各两条文字。每条必须全文相等、发送人一致、归属一致，并在读取前后两次元信息采样中均确认微信运行且非前台、未锁屏。阶段一仅表示四条实时样本通过，六条总样本仍需阶段二完成。

第一阶段达到四条后程序自动结束并释放状态锁。确认监听已停止，再由同一发送人在两个会话各发第三条文字，并记录用户完成发送的时间。之后恢复同一个私有检查点：必须恢复既有四条结果、仅新取得两条结果、旧事件不重报，最终六条指定文字均各一次。恢复游标本身不自动证明停机补采，需同时保留实际暂停与发送步骤证据。

本轮的后台证据仅证明读取前后采样状态，不推断采样间隙、锁屏、最小化或长期状态。

主要脱敏证据：

- `artifacts/verification/wechat-selected/2026-10-27/result-summary.json`：最终六条样本汇总、范围与未验证能力。
- `phase-live-01.json`、`phase-resume-01.json`：分阶段逐条身份与后台状态核对、恢复数量及事件重报计数。
- `pause-window.json`：实际监听停止、用户确认停机期间发送以及重启的时间记录。
- `selection-metadata.json`：两个会话精确解析后的元信息核对，不含名称或内部账号标识。
- `synthetic-tests.txt`：30 项合成测试输出。
- `environment-and-cleanup.json`、`sanitized-evidence-scan.json`：固定依赖、代码哈希、私有文件权限、临时副本删除及公共证据脱敏检查。

上述同目录文件不含原文、实际联系人名称、账号标识或密钥。测试结束后原版微信签名校验通过，主程序哈希与初始化前一致；临时副本已删除，监听已结束，检查点文件锁已释放。检查点和本机密钥按 0600 保留在 0700 私有目录中，便于后续受控测试，不自动继续采集。

## 程序与私有状态

- `scripts/configure_wechat_selected_test.py`：只读联系人库，精确解析用户选择；重名、缺字段或无效密钥均明确停止。
- `scripts/wechat_selected_reader.py`：只查询选定会话表的新文字；发送者取同分库 `Name2Id.rowid` 映射，群前缀仅在与已确认发送者完全相等时去除。
- `scripts/run_wechat_selected_test.py`：有限时长两阶段测试入口；要求准确的每阶段会话／编号集合、正文、发送人及后台状态均匹配。
- `scripts/prepare_wechat_read_test.py --database-scope contact_metadata_only`：额外联系人元数据初始化范围，prepare/capture 以 manifest 核对一致性。

进度与匹配结果先共同原子保存，再返回观察事件。检查点绑定本轮配置、账号目录、数据库密钥与盐值，并用 HMAC 校验；状态文件 0600、所在目录 0700。检查点不保存普通聊天正文、联系人名称、账号标识或原始密钥。两个采集进程不能同时占用同一检查点。

公开证据放 `artifacts/verification/wechat-selected/2026-10-27/`；选择名称、内部会话标识、密钥和检查点放 `artifacts/private/wechat-selected/2026-10-27/`，不进入 Git。公开报告仅包含受控别名、编号序号、匹配结果、时间及经过摘要处理的事件／发送人标识。

本轮沿用已记录的 Python 3.12.14、`sqlcipher3-wheels==0.5.7`、`zstandard==0.25.0` 和本机原生状态探针，没有增加全局依赖。

本轮证明的是同一发送人在两个选定会话中交替发送六条短文字、以及一次正常退出后恢复的最小流程。没有将其扩大为所有会话、所有用户、崩溃恢复、突发刷屏、100 条完整规模或跨平台发布已通过。
