# 持续采集与停止恢复

更新于 2026-11-01。本轮实现从已实测的 Windows 微信 4.1.15.56 读取路线继续，保留旧 Mac 六条测试与恢复证据，不改历史包或用户配置。新版 Web、模型与通知另行接入。

## 本轮范围

- 复用用户在成功 r2 中选定的一处私聊和一处群聊。首次导入后固定账号、程序路径与两个会话，不自动扩到其他会话或分库。
- 首次启用建立 MAX(local_id) 基线，只保存此后所选会话的新纯文字；测试编号仅用于验收，实际采集不按编号过滤。
- 持续运行直到 Ctrl+C 或明确异常停止；没有原四条测试的五分钟结束限制。
- 消息正文与来源游标在同一个本地 SQLite 事务中提交。重开同一目录使用已提交游标，补读采集停止期间、微信本地数据库实际收到的消息，不重建基线。
- 微信在前台、锁屏或状态无法确认时暂停提交，恢复正常后台状态后再补读；微信进程退出则停止，重开启动器匹配当前进程。

本轮直接交付 Windows 启动入口。通用 reader/store 在 Mac 隔离环境以真实 SQLCipher 合成库测试，不能替代新版采集服务的 Mac 客户端接入或 Windows 原生实机验收。原 Mac 工具与证明继续保留。

## 存储与一致性

新包自身目录中的 `collector-data` 为当前用户受保护的本机数据目录：

| 文件 | 用途 |
| --- | --- |
| `private/scope.json` | 固定所选账号、会话、会话类型和本轮验收编号 |
| `private/keys.json` | 从原 r2 配对文件复制的本机密钥；启动重新认证固定三库，不重新扫描进程内存 |
| `private/store/collector.sqlite3` | 所选新文字、发送人、源时间、取得时间、来源游标与基线 |
| `private/store/collector.identity.json` | 存储版本与范围绑定 |
| `private/store/.collector.lock` | 单实例锁，运行期间持有 |

数据库为**权限保护的普通 SQLite，未加密**。这些文件全部留在本机，不进入 Git 或交付包，不回传。Windows 首次创建当前 SID 专属 DACL，恢复时只核验既有权限；POSIX 合成运行要求目录 0700、文件 0600，不自动修复用户权限。

目标数据库用 DELETE journal 与 synchronous=FULL。先读取所选来源表的一小批数据，再检查来源和原生状态，最后一次事务保存新文字和全部本批游标；事务失败不提前提交进度。稳定来源标识去重，正文相同而物理 ID 不同的消息分别保存。首次基线仅一次；检查点损坏、缺失、范围改变、源文件身份／salt／key 改变、分库集合变化、来源 ID 倒退或原有表消失均停止，不静默跳过旧消息。

来源仍是 SQLCipher `mode=ro`、query_only 和短事务。正常 WAL 读取可更新 SHM 锁元信息；不改源库记录，不主动 checkpoint/rekey，不复制活库当一致快照。每轮最多每分库／会话 128 行，正文合计最多约 16 MiB；剩余数据保留下一轮，尾部媒体只推进位置不读取媒体正文。未知压缩停止，不能丢弃后直接推进游标。

## 运行和状态

1. 将新包完整解压到一个新的本机目录，运行 `Start-Collector.cmd`。
2. 首次选择此前成功 r2 运行目录的 `private/selected-config.json`。同目录必须保留配对的 `selected-keys.json`。此步骤不选择第三包的 `validated-message0-key.json`。
3. 保持微信登录、联网、在后台，屏幕解锁。READY 出现时已建立并保存首次基线，采集已运行，无需再按开始回车。
4. 每十秒或状态变化显示运行／暂停和本次新增、本地累计计数；每轮写脱敏 `status.json` 心跳。
5. 停止时按一次 Ctrl+C，等待显示“已停止”和启动器结束提示。重启用**同一个包目录**的 `Start-Collector.cmd`；已有配置自动复用，不再选择旧 r2。

监督器与采集子进程分开：初始化最多 120 秒，进入采集后仅按心跳是否停滞监督，正常空闲和暂停有新心跳就可持续等待，不限制总时长。心跳 90 秒不前进时只终止自己持有的子进程，不关闭微信。Ctrl+C 先写本次 stop.request，给予子进程十秒正常保存和关闭；必要时仅回收本次子进程。已有事务由 SQLite 恢复，重启不能承诺一定是优雅退出，但不自动清空状态。

每次公开回传保存在 `results/<本次时间>-continuous/`：`result-to-send.json`、`supervisor.json`；`status.json` 仅是当前进度。报告只有阶段、计数、时间与验收布尔，不包含联系人、会话名、正文、密钥或私人路径。普通 `status=通过` 仅表示生命周期和检查点正常结束；六条恢复验收需按下面独立核对，不能由退出码 0 推定。

## Windows 两阶段恢复验收

使用原先获授权的私聊和测试群，由同一位受控发送人配合；编号只显示在本机控制台和私有配置。

1. 首次 READY 后，发送界面所列前四条，私聊和群各两条，每条各一次。等待“本次新增”增加、采集完成一轮保存后，按一次 Ctrl+C，保留第一次的两份报告。
2. **确认采集程序已停止**后，再发送界面事先给出的第三条私聊编号和第三条群编号，各一次；微信保持登录并在后台。
3. 两条发送后，重开同一个 `Start-Collector.cmd`。看到恢复提示后不要重复发送任何旧编号，等待本次新增计数增加，再 Ctrl+C，保留第二次的两份报告。

接受条件：第一次四条正文／发送人／归属匹配、各一次；第二次 `resumed_from_checkpoint=true`，先前四条已保存，停机两条只新增一次；最终六个编号均 `matched_count=1` 且 `verified=true`。结合两次报告的基线、开始／停止、源时间与取得时间核验停机发送窗口。若两个会话还收到其他新文字，总计数可能大于六，以逐码摘要为准。采集停止时尚未进入源库的消息只能在微信以后实际收到时补采。

只回传两次的公开 JSON，必要时用文件名区分；不要发送整个结果目录、collector-data、private、数据库或任何密钥文件。

## 验证证据与边界

源码测试覆盖真实 SQLCipher 合成 DB/WAL、只读、分页、范围隔离、重复同文、原子提交、真实子进程提交前／后突然退出、跨进程锁、前台暂停、源变化、损坏状态拒绝、监督心跳与优雅停止。证据目录为 `artifacts/verification/continuous-collector/2026-11-01/`。

独立一万条合成专项：首次保存 5,000 条，真正关闭 reader/store 后再产生 5,000 条；恢复原状态并补回 5,000 条，空重启不重报，10,000 条正文／会话／来源 ID 精确对照，旧正文与未选会话正文读取为零。它是快速合成压力测试，不能称长期真实运行或 Windows 实机恢复通过。

Windows 新包已在下述两阶段实机中完成正常运行、私有权限核验、Ctrl+C 和真实来信恢复。单实例锁竞争拒绝、真实崩溃／强杀恢复、锁屏、最小化、微信升级、来源迁移、更多分库及长期稳定性仍为未验证。源记录删除或客户端根本未收到的消息无法凭检查点重建；当前纯文字增量不处理撤回、编辑、图片或语音。
