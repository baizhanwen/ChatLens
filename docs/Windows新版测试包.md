# Windows 多会话与收发统计测试版

当前测试版本为 `ChatLens-Windows-Web-20261101-r7.zip`，旧r6及更早包保留原样，r4仍只保留为未发布的中间候选。r7修复目录加载的状态、错误反馈和重试，慢目录读取与网页状态查询分离。继续保留r6的同源微信程序树两轮只读映射账号核验、主进程前后台保护和账号／范围隔离。

本版继续复用此前同一台电脑、同一账号已测通的整个原 `collector-data`，不重取密钥、不重建数据或安装全局依赖。用户回传的r6实测整理含诊断摘录：Windows11 build26200／微信4.1.15.56 x64，映射账号核验两轮、5/5成员均完成，原范围实际collecting；会话选择页失败。此项按用户报告记录，不代表完整收发／恢复对照或另一台电脑通过。报告中的1.5秒SQL超时仍是假说，开库和HMAC原本不在该局部计时内。r7真实目录读取、多选及完整消息顺序仍待本轮实机核对。

## 保留旧数据后启动

1. 在旧采集或网页控制台按一次 `Ctrl+C`，等旧进程正常退出；不要强删锁、配置或检查点。
2. 把新版 ZIP **完整解压到新的固定磁盘文件夹**，保留旧包。不要覆盖旧包，也不要解压到旧 `collector-data` 或 `private`。
3. 双击新包 `Start-ChatLens.cmd`，选择此前原私聊和测试群已测成功时使用的**整个旧 `collector-data` 文件夹**，继续使用同一台电脑和同一账号。不是配置 JSON、`private`、数据库或一个新建空目录。无需复制、搬动或上传旧数据，不重置原密钥。
4. 使用自动打开的 `127.0.0.1` 微信接入引导。完整地址含当前会话凭据，不可发送或提交；双击 `web/index.html` 只是虚构预览。
5. 页面分别核对微信进程、账号读取范围及读取条件。**尚未核验不等于未登录**。原账号已经登录时保持现状，不重复退出登录或初始化密钥；先查看固定原因，再点击“重新检测微信”，无需关闭工具或重新选择数据目录。若原账号尚未登录，请先在原 Windows 微信 `4.1.15.56` 中完成登录。
6. 原账号与读取条件核验就绪后，点击开始采集，再进入工作台核对原数据。程序只在用户确认后恢复原范围及检查点；不会因为打开网页就自动扩大范围或把另一账号当作原账号。

引导按“微信程序 → 账号读取核验 → 读取配置 → 关注会话 → 采集消息”展示状态。

原消息、原启用起点、原检查点以及 `private/assistant` 下的模型配置和 AI 历史原位保留。新范围不覆盖旧范围；新旧入口不能同时写同一个目录。原微信不在线时可点“查看已保存消息（离线）”，工作台的“连接微信与使用引导”可返回接入页；登录原账号后仍可重试，不会永久锁为只读。源码显式 `--read-only` 兼容入口保留，正常双击启动不会自动使用它。

r2启动器要求原程序路径、`ProductVersion` 字面匹配及非零主窗口句柄，候选为零时传入永久 `--read-only`，所以该路径不能修改范围。r3的启动器窗口枚举只提供暂时元信息；Python重新核对原路径和版本，隐藏托盘的唯一根进程也可成为候选，但必须进一步确认账号读取核验完成。该核验不代表微信网络在线，r3不根据窗口状态猜测账号。

主进程候选优先唯一匹配的有效主窗口，即可见且无所属窗口，不读取标题；隐藏辅助窗口不计为主窗口。多个有效主窗口保持歧义，不改选父启动器；没有有效主窗口时，才允许唯一根进程作为托盘候选。原路径、受支持版本、架构、创建时间及账号读取核验仍保留。

## r6 账号读取证据

账号依据只在原程序的一个唯一连通进程族内核对，最多16个成员。成员都须满足原程序完整路径、x64架构、受支持版本与创建时间；查询前后身份和父子关系必须稳定。主进程PID继续绑定采集与前后台判断，辅助进程不会替代它，同源辅助窗口在前台也暂停。

每个成员完整执行两轮映射元信息查询，先用 `VirtualQueryEx` 和 `QueryVirtualMemoryInformation` 区分数据文件映射与页文件共享区，再用 `K32GetMappedFileNameW` 获取完整数据文件路径。两轮都必须正面匹配原账号根；任何其他账号根均不匹配，成员变化、部分查询、空结果、截断或未知分类保持未核验。不会把查询失败当成匿名区域静默跳过，也不会用旧数据库可解密来替代当前账号依据。

所有成员与两轮共享3秒、32768区域的预算，整个独立子进程硬超时6秒。账号步骤仅查询元信息，不读内存页、聊天正文或密钥，不使用PSS文件名、不复制句柄；正式采集仍按原明确选择的会话范围读取新文字。

## r7目录读取与重试

点击修改关注范围后，页面应区分准备、读取中、失败和真实空结果。读取成功自动列出可选名称，失败提供原因与重新读取；不会把未就绪显示成“没有匹配的会话”。读取仅查询表名和联系人元信息，不导入历史正文，不改变原关注范围。目录任务使用共享30秒合作式预算，在SQL首个schema查询前安装中断检查；阻塞中的原生文件IO不能保证硬终止，旧任务未退出时不会再启动第二个任务。目录任务受预算和取消机制限制，切范围、账号变化或退出时旧结果作废；状态查询与原采集不因持锁读目录而阻塞。实际Windows性能与失败根因需由本轮诊断补充，不以增加时间限制宣称已解决。

## 关注多个会话

在“设置 → 管理关注范围”中点击“修改关注范围”，加载可选名称。可以明确选择1—50个私聊或群聊，同类也能多选；搜索不会清掉已经手动勾选的项目。只有确认“启用所选关注范围”才切换，查看名称不会自动扩大采集。

旧范围使用原 `collector-data`。新增范围位于原目录的 `private/profiles/<范围摘要>/`，各自保存消息、基线、游标和 AI 历史，不复制旧正文。重开原 `collector-data` 会恢复已选范围；在“已保存的关注范围”可切回原范围继续原检查点。

同一账号的新范围可以首次沿用原模型配置，已有目标配置不覆盖；模型设置和 AI 历史之后各自保存。不会跨账号复用密钥、消息、配置或 AI 对话。本次入口不会为另一个账号自动初始化读取能力。切换会使旧页面标记失效，旧请求与迟到结果不能进入新范围。

## 核对收到和本人发出

本人身份经账号、联系人精确 ID 与所选普通私聊发送者依据交叉核验；不用昵称“我”或固定分片行号猜测。只查询所选私聊的发送者元数据，不读取或导入历史正文。证据不足时标为未知；首次只选群聊可能没有足够依据。

可以直接问“今天谁给我发消息了”“今天我发了几条消息”“今天收到和发出分别多少条”。本机统计不需要模型配置，收到、发出和未知分开；未知不计入来信。总结与业务分析才使用本人设置的模型，并由页面确认目标及相关文字范围。

## 本轮实机顺序

| 步骤 | 操作 | 应核对的结果 |
| --- | --- | --- |
| A 引导 | 保持原账号登录，用原资料启动，重新检测后确认账号读取核验状态；仍未核验时导出连接诊断 | 未就绪原因明确，不推断为未登录，不重取密钥；未确认前不称采集中 |
| B 原范围 | 先不改范围，查看原会话、旧消息、配置及采集状态 | 原资料仍在，Key不回显，状态依据真实采集而非页面可打开 |
| C 多选 | 自行选择至少两个可配合私聊和一个测试群并启用 | 新范围单独开始，不导入旧正文，原范围仍列为可恢复 |
| D 收发 | 显示正在采集后，请朋友在私聊和群各发一条新文字，再由本人手机各回复一条 | 正文、会话与收到／本人标记对应，统计三桶合计正确 |
| E 恢复 | 正常停止；停止期间请朋友发两条，重开同一目录，经引导核验并开始采集 | 恢复上次范围与检查点，旧消息不重报，停机文字补回 |
| F 隔离 | 显式切回旧范围，再恢复新范围；保留一个旧标签页观察 | 各自消息、AI历史和采集位置保持，旧标签不能操作新域 |

测试文字和真实联系人名称只需在本机核对，不必发到聊天。无需为了验证本机统计配置付费模型，也不要让自动化工具代发微信消息。

## 反馈与运行边界

若读取核验仍未完成，先在接入页点击“导出连接诊断”，只回传生成的 `ChatLens-Windows-Connection-Diagnostics.json`。该操作只取本次缓存的固定状态、布尔值与有界计数，不再次触发微信扫描、聊天读取或模型调用。导出不含PID、私人路径、账号和联系人标识、姓名、聊天、密钥、配置或会话凭据。

正常退出后的公开报告仍为新包 `results/<本次时间>-web/result-to-send.json`；必要时按故障说明另取采集公开报告。不要回传 `collector-data`、`private`、JSON配置、密钥、数据库、完整登录地址或真实聊天截图。

包内固定 Python `3.14.10` Windows x64、`sqlcipher3==0.6.4`、`zstandard==0.25.0` 与标准库 SQLite；不安装全局 Python、Node、Codex、pip，不注册服务或开机自启。逐文件摘要、固定上游来源与许可证见 `WEB-MANIFEST.json` 及包内许可。消息与配置是本机权限保护的普通文件，消息 SQLite 未加密。

此前 Windows 两会话六条与一次停止恢复的历史结论仍有效于当时版本和样本。新版多会话、收发统计、新网页、长时间稳定性、锁屏、其他微信版本、其他客户设备需分别验收，不能用旧结果替代。

保留的r6包为15,644,559字节／95文件，SHA256 `b1c61e551e16000b317baa458d0a06a23dcc0f7901633c8d1bcda936943d25dd`。38个公开源、3个固定缓存的全部payload、CRC、清单白名单、导入闭包、4份许可和旧6包摘要核对均通过，固定便携运行依赖未增加。旧6个本机包（含r5及未发布r4候选）保留原样；新API合成检查、已回传的单机自检与真实微信接入分别验收，真实微信映射与新消息仍未验证。

初始化、正在采集、暂停及心跳过期来自本轮独占采集器的实际心跳；只启动了进程或原资料可读，都不代表已开始接收。准备阶段不会提前跳到工作台；暂停时可查看已有消息和实际原因，也不能重复启动第二个采集器。

## 账号核对失败时

账号探针只查询已校验程序树的映射元信息。官方接口说明见 [VirtualQueryEx](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualqueryex)、[QueryVirtualMemoryInformation](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-queryvirtualmemoryinformation) 与 [GetMappedFileNameW](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-getmappedfilenamew)。它们返回区域属性和文件名，不要求读取聊天内存页。原生调用仍在6秒自有子进程内；缺失足够的当前账号证据时保持隔离。

如果页面显示尚未核验，而原账号已经登录，请保持原资料和登录状态，不删除文件、不反复退出登录、不重做密钥提取。等待当前阶段结束，重新检测一次；仍未核验时按上文手动导出连接诊断，用计数定位缺少的元信息。页面提供“查看已保存消息（离线）”时，可先浏览，再通过“连接微信与使用引导”返回，无需重启工具；账号不匹配或读取域未核验时不会开放旧消息。读取核验不证明网络连接状态，原生权限、映射查询行为和耗时仍需本机实测。

连接诊断保留进程族数量，并新增映射查询数量和两轮完成标记。以下既有字段保持只含计数：

| 字段 | 含义 |
| --- | --- |
| `family_process_count` | 纳入严格核对的进程族成员数 |
| `family_processes_completed` | 已完成当前轮完整映射查询的成员数 |
| `main_database_names_seen` | 主进程中看到的数据库名称数量 |
| `helper_database_names_seen` | 辅助进程中看到的数据库名称数量 |

这些计数不包含PID、身份、名称或文件路径，仅帮助定位哪一层缺少证据；辅助计数非零本身不表示账号已核验，也不证明已解决实机问题。

进程候选使用微软文档的 [PROCESSENTRY32W](https://learn.microsoft.com/en-us/windows/win32/api/tlhelp32/ns-tlhelp32-processentry32w) 元信息及 [EnumWindows](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-enumwindows) 的窗口PID，不读窗口标题或聊天。对原程序核对路径、数字版本、架构和创建时间；托盘／隐藏窗口不再直接导致永久只读，候选仍须继续核验账号读取范围。
