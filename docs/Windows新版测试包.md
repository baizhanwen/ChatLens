# Windows 多会话与收发统计测试版

版本为 `ChatLens-Windows-Web-20261101-r2.zip`。这是面向此前已经通过读取验证的 Windows 账号的升级测试包，复用原 `collector-data`，不要求重新提供密钥。真实 Windows 新版执行、多会话新消息、收发核对及停止恢复仍须按本说明验收；打包检查和本机合成测试不替代实机结论。

## 保留旧数据后启动

1. 在旧采集或网页控制台按一次 `Ctrl+C`，等旧进程正常退出；不要强删锁、配置或检查点。
2. 把新版 ZIP **完整解压到新的固定磁盘文件夹**，保留旧包。不要覆盖旧包，也不要解压到旧 `collector-data` 或 `private`。
3. 双击新包 `Start-ChatLens.cmd`，选择此前已测成功的**整个旧 `collector-data` 文件夹**。不是配置 JSON、`private`、数据库或一个新建空目录。无需复制、搬动或上传旧数据。
4. 保持原账号的 Windows 微信 `4.1.15.56` 登录、联网。启动器继续核对原程序路径与主窗口；来源不匹配时不把另一账号当作原账号。
5. 使用自动打开的 `127.0.0.1` 授权页面。完整地址含当前会话凭据，不可发送或提交；双击 `web/index.html` 只是虚构预览。

原消息、原启用起点、原检查点以及 `private/assistant` 下的模型配置和 AI 历史原位保留。新范围不覆盖旧范围；新旧入口不能同时写同一个目录。原微信不在线时只读浏览已保存范围，要继续采集或新选范围须登录原账号后关闭入口再重开。

## 关注多个会话

在“设置 → 管理关注范围”中点击“修改关注范围”，加载可选名称。可以明确选择1—50个私聊或群聊，同类也能多选；搜索不会清掉已经手动勾选的项目。只有确认“启用所选关注范围”才切换，查看名称不会自动扩大采集。

旧范围使用原 `collector-data`。新增范围位于原目录的 `private/profiles/<范围摘要>/`，各自保存消息、基线、游标和 AI 历史，不复制旧正文。重开原 `collector-data` 会恢复已选范围；在“已保存的关注范围”可切回原范围继续原检查点。

同一账号的新范围可以首次沿用原模型配置，已有目标配置不覆盖；模型设置和 AI 历史之后各自保存。不会跨账号复用密钥、消息、配置或 AI 对话。本次入口不会为另一个账号自动初始化读取能力。切换会使旧页面标记失效，旧请求与迟到结果不能进入新范围。

## 核对收到和本人发出

本人身份经账号、联系人精确 ID 与所选普通私聊发送者依据交叉核验；不用昵称“我”或固定分片行号猜测。只查询所选私聊的发送者元数据，不读取或导入历史正文。证据不足时标为未知；首次只选群聊可能没有足够依据。

可以直接问“今天谁给我发消息了”“今天我发了几条消息”“今天收到和发出分别多少条”。本机统计不需要模型配置，收到、发出和未知分开；未知不计入来信。总结与业务分析才使用本人设置的模型，并由页面确认目标及相关文字范围。

## 本轮实机顺序

| 步骤 | 操作 | 应核对的结果 |
| --- | --- | --- |
| A 原范围 | 先不改范围，查看原会话、旧消息、配置及采集状态 | 原资料仍在，Key不回显，状态依据真实采集而非页面可打开 |
| B 多选 | 自行选择至少两个可配合私聊和一个测试群并启用 | 新范围单独开始，不导入旧正文，原范围仍列为可恢复 |
| C 收发 | 显示正在采集后，请朋友在私聊和群各发一条新文字，再由本人手机各回复一条 | 正文、会话与收到／本人标记对应，统计三桶合计正确 |
| D 恢复 | 正常停止；停止期间请朋友发两条，重开同一 `collector-data` | 恢复上次范围与检查点，旧消息不重报，停机文字补回 |
| E 隔离 | 显式切回旧范围，再恢复新范围；保留一个旧标签页观察 | 各自消息、AI历史和采集位置保持，旧标签不能操作新域 |

测试文字和真实联系人名称只需在本机核对，不必发到聊天。无需为了验证本机统计配置付费模型，也不要让自动化工具代发微信消息。

## 账号核对失败时

新增账号探针只捕获指定微信进程的文件句柄名称元信息，不克隆进程内存、不读取聊天正文。它使用微软文档的 [PSS_CAPTURE_FLAGS](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/ne-processsnapshot-pss_capture_flags) 中句柄与名称两项，并按 [PSS_HANDLE_ENTRY](https://learn.microsoft.com/en-us/windows/win32/api/processsnapshot/ns-processsnapshot-pss_handle_entry) 解析。原生调用放在最长6秒的独立子进程；未能核对唯一原账号时拒绝源读取，不退回猜测。

如果页面显示无法确认账号，先确认原账号已登录，等待当前阶段结束；不要删除任何资料来重试。正常关闭本次入口后，可以在原账号重新登录后重开；微信不在线时仍可选原资料只读查看。反馈公开报告中的 `manager_final_reason` 和 `account_probe_reason` 即可，不需要发送私人路径、配置或聊天。原生API权限、句柄捕获行为和耗时仍是本次Windows实测的一部分。
