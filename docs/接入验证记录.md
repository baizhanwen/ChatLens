# ChatLens 接入验证记录

本次真实只读探针运行于 2026-10-26（Asia/Shanghai），macOS 27.0 build 26A428，MacBook Pro / M1 Pro / 16 GB / arm64，Python 3.9.6。用户已明确本次先完成开发版并记录权限受限，不继续申请权限或读取个人聊天。

主读取路线按用户最新要求为 **指定窗口截图 → 视觉模型结构化识别 → 消息事件**。AX/UI Automation 仅辅助获取客户端和窗口状态；OCR 为单独标记的可选降级。默认由事件触发，绝不持续截屏。开始采集产生一次 manual_start 事件，随后可由用户“读取一次”、授权窗口重新进入前台、已接入的外部事件触发；事件经稳定等待、冷却和图像 hash 去重。默认 periodic_fallback_seconds=0。

## 代码与模拟验证

`services/worker/adapters.py` 提供八个隔离适配器（四端视觉主路线与四端AX/UIA降级接口）、统一 `probe/start/stop/health/events`、`WindowVisionAdapter.trigger(reason)` 和 `checkpoint()`。`vision.py` 由主工程提供可替换视觉模型，未配置时明确暂停；本机仅回环地址或用户明确授权的HTTPS云端截图外发范围才可调用。

开始时必须指定 account_id、conversation_id、expected_conversation、window_id 及 acknowledged_scope。模型须确认画面标题与白名单会话一致，否则暂停并登记缺口。识别截图只限指定且属于目标客户端的可见前台窗口；临时文件权限0600，目录0700，在识别前读入内存后删除；不截全屏。模型输出的ID不作为原平台ID。无法确定发送人保留unknown，无法读到原始时间保留null元信息并标注“取得时间”；编辑/撤回没有稳定原平台ID，不推断成功。

触发健康信息包含 trigger_count、capture_count、model_calls、skipped_unchanged、last_trigger_reason、next_allowed_at、故障与缺口。元信息检查默认3秒，不截屏。AX内容变化observer尚未实现；滚动、停留/idle仅提供事件入口，原生可靠观测未验证。

macOS额外提供用户显式启用的关注模式（watch_changes默认false）：ScreenCaptureKit只订阅指定窗口，1fps本地内存像素处理，ROI默认归一化 `[0.22,0.12,0.77,0.64]` 排除常见侧栏、标题和输入框；输出只有变化元信息，不保存或外发帧。变化触发VLM读取，稳定等待、防抖、max_wait=5秒与cooldown=10秒限制调用；max_wait受冷却下限约束。光标隐藏，ROI可自定义以适应不同布局。窗口非前台/最小化/隐藏/锁屏时停止流，并在再次合格时恢复；识别时还会做前台与裁剪区域中的会话标题核对。

关注模式需要用户明确知晓：它持续在本机低频检查局部像素变化，**不是持续调用视觉模型**。不开启关注模式时，停留前台且没有手动触发不能保证自动取得对方新消息。开启后仍无法保证看到高速刷屏移出窗口的全部消息；检测到前后无可见消息重叠时登记possible_gap_no_visible_overlap，不推断窗口外内容。相同文本且可见画面完全相同可能无法区分新旧，存在缺口。Windows关注模式目前不支持。不得称为全会话实时采集。

VLM只接收裁剪后的指定窗口图像：vision_crop为归一化 `[x,y,width,height]`，默认参考值 `[0.25,0,0.75,0.85]` 意在保留标题与消息、排除左侧栏与输入框，但不同客户端和窗口布局必须由用户确认。crop_acknowledged默认false，未确认时暂停为vision_crop_not_confirmed；crop失败不回退整窗。macOS先本机裁剪再将字节交给模型，Windows脚本只保存内存裁后的PNG。用户须保证裁剪内仅是授权会话区域，仍须授权云端外发该裁剪区域。默认参考框没有真实微信/QQ布局验收，不能自动保证排除所有非白名单内容。

一帧的消息事件与完整匹配状态通过 `on_batch(events,checkpoint)` 在同一SQLite事务持久化，失败回滚后源ID重试不变；恢复时相同可见帧不新增消息。逐条on_event仅为接口兼容，持久化集成应采用批次回调。

模拟测试入口：`python3 -m unittest discover -s tests -p test_adapters.py -v`。25项测试覆盖权限/平台受限、白名单会话不匹配、缺模型、云端授权、锁屏前不截图、重复文本出现次数、批事务失败重试及checkpoint恢复、mock-clock防抖/冷却与连续变化max_wait、关注模式显式开关与销毁、无周期截图、hash相同跳过模型、裁剪确认与裁后字节流、窗口停靠入参/恢复。模拟测试不能作为真实客户端或模型验收。

macOS本机原生构建入口：`sh scripts/build_native_macos.sh`。生成 `scripts/native/bin/macos-probe`、`macos-ocr`、`macos-watch`、`macos-crop`、`macos-dock`，优先使用本机编译可执行文件；未构建时需要Swift/Xcode Command Line Tools回退执行。二进制为本机arm64、临时签名，不代表另一架构、分发签名或客户端真实读取通过。

## 其他系统与后续真实验收

在Windows PowerShell中执行：

```powershell
python scripts/probe_clients.py --platform wechat --output docs/evidence/windows-wechat-probe.json
python scripts/probe_clients.py --platform qq --output docs/evidence/windows-qq-probe.json
powershell -NoProfile -File scripts/native/windows_probe.ps1 -Platform wechat
```

`windows_capture.ps1 -WindowHandle <明确选定的目标窗口句柄> -Output <临时PNG>`只捕获前台非最小化指定窗口，使用PrintWindow。某些GPU界面可能黑屏或缺内容，必须真实核对。此脚本本次未执行，不能作为Windows读取或构建通过证据。

真实验收步骤：

1. 在对应真实系统安装并启动指定客户端，记录系统/客户端/应用/视觉模型版本；先运行元信息探针，按需手动授予系统权限。
2. 由用户选择测试账号、白名单会话和指定窗口，使用完全受控的至少100条文本样本，保留本地原始对照；模型应使用本机模型，云模型须另行明确截图外发范围。
3. 逐条核对发送人、原始时间（未可见时应为空）、内容、顺序、重复文本。分别报告漏采率、重复率、视觉识别错误，保留失败样本，禁止以回放替代。
4. 分别验证前台、遮挡、后台、最小化、滚动、切会话、锁屏、客户端关闭重启、权限撤销；状态变化时应暂停/记录缺口；模型会话标题核对失败不入库。
5. 验证触发次数、截图次数和模型调用次数：无事件时不截图；事件密集时防抖/冷却；相同图像跳过VLM；手动重试可恢复；三次同因处理错误应停为受限并记录诊断。
6. 验证应用关闭重启及checkpoint恢复、采集白名单与全局暂停、删除会话清理；核对临时图像已删除，日志无原文/密钥。
7. 每端独立保存版本、时间、原始对照路径和指标，不同系统、客户端、模型不能互相代替。四端均有合格证据后才可考虑完整支持声明。


## 关注模式原生自测证据

`macos-watch --self-test` 创建只包含完全虚构文本的AppKit窗口，记录8帧和7次局部像素变化事件；[native-watch-selftest.ndjson](evidence/native-watch-selftest.ndjson)只含元信息，未落盘截图、未调用模型。额外使用 `--self-test --pause-test` 验证合成窗口最小化、暂停和恢复，记录见[native-watch-pause-selftest.ndjson](evidence/native-watch-pause-selftest.ndjson)。首次暂停自测因测试窗口未带miniaturizable样式没有实际最小化，证据保留[native-watch-pause-attempt1.ndjson](evidence/native-watch-pause-attempt1.ndjson)，修正测试窗口后重测，避免把未发生的暂停记为通过。

上述为 **本机原生组件＋合成窗口验证**，不是微信/QQ真实消息或真实VLM质量验证。实现参考Apple官方 [SCContentFilter](https://developer.apple.com/documentation/screencapturekit/sccontentfilter)、[minimumFrameInterval](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/minimumframeinterval)、[SCStreamOutput](https://developer.apple.com/documentation/screencapturekit/scstreamoutput) 文档；没有引入外部聊天库或旧的解密项目。


## 截图范围与原生小窗停靠

`macos-crop --self-test`在本机处理完全合成的100×80左右色块图，裁为右侧50×80，验证左侧隐私区像素已移除；[native-crop-selftest.json](evidence/native-crop-selftest.json)为真实本机图像处理结果，不能替代微信/QQ布局验收。Python适配器测试验证只有裁后的字节被送入模型函数，未确认裁剪时不截图。

`dock_window(client,window_id,bounds)` 与 `restore_dock(record)` 仅移动/调整真实客户端窗口，供“左侧真实微信/QQ小窗＋右侧分析窗”的并排模式使用，不把聊天截图冒充可交互客户端。macOS通过窗口ID→PID→bundleID验证目标，AX只读取几何属性，以唯一几何匹配窗口后设置位置/大小与raise；没有读取聊天原文、点击发送、跨进程SetParent或伪造系统内嵌。Windows脚本通过窗口句柄→PID→进程名检查，调用SetWindowPos；未实机验证。

本机仅运行 `macos-dock --platform wechat --preflight` 与 `--platform qq --preflight`，均返回 `accessibility_permission_missing`、`changed=false`，证据：[微信停靠预检](evidence/macos-dock-preflight-wechat.json)、[QQ停靠预检](evidence/macos-dock-preflight-qq.json)。未授予权限、未移动个人客户端窗口，真实停靠与恢复保持受限/待验收。25项适配器测试中的停靠逻辑使用模拟runner与只读原生预检，不能作为真实移动通过。
