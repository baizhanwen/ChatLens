# Windows 兼容性验证矩阵

这是本机单用户、明确选择会话的测试工具。某台电脑上的接口自检、真实微信读取、其他电脑和不同客户端版本分别记录，不将其中一项通过等同于通用可用。

| 环境／能力 | 状态 | 已知证据与边界 |
| --- | --- | --- |
| 原测试电脑、微信4.1.15.56、旧受控读取及一次停止恢复 | 通过 | 既有两会话六条与恢复证据保留；不替代新版网页和账号核验验收 |
| 同一电脑、r5格式账号核验 | 失败 | 所有5成员枚举完成，但PSS路径证据不足，未启动采集 |
| 同一电脑、自建文件的K32映射路径自检 | 通过 | 用户回传工具20261101-02 JSON，路径完整匹配、无截断且资源清理完成；不读取微信 |
| 原测试电脑、Windows11 build26200、r6完整程序树映射账号核验 | 通过 | 用户回传r6实测整理中的诊断摘录：两轮、5/5成员、6条匹配数据库路径、名称查询失败0，账号matched、采集collecting；不是在开发Mac独立执行，见r7目录修复轮的received-r6-feedback-summary.json |

## 实现上的通用边界

- 地址上下限和页大小由本机`GetNativeSystemInfo`返回，账号资料根来自本人选择的本机私有配置。程序路径、版本、架构、PID与创建时间逐次核验，不写死开发机账号、Windows构建号或地址。
- `VirtualQueryEx`完整遍历后，用`QueryVirtualMemoryInformation`明确区分数据文件和页文件共享区。仅对已识别的数据文件查询名称；名称返回0、截断、未知区域类别或不稳定时保持未核验，不把错误猜成匿名区。
- 同一程序树必须完整检查两轮，每轮都仅指向原账号根，最终程序树身份仍相同。出现其他账号、不完整或无证据时不读取源会话，也不以旧库可解密代替当前进程资料关联。
- 账号核验只建立本机程序与资料的关联，不代表微信网络在线。既有消息可读、网页打开、子进程存活、接口自检通过都不等于已收到新消息。

## 每个新环境的验收顺序

1. 记录系统与客户端版本；使用现有便携Python进行自建映射路径自检，留存固定计数报告。
2. 用该电脑自己的完整`collector-data`启动新版，检查账号核验、当前实际阶段及诊断；不复制开发机或别人的密钥和配置。
3. 明确开始后，在选定私聊和群聊手动核对新的收到及发出文字，并检查来源、统计和原消息引用。
4. 正常停止，在停止期间发送受控文字；重开同一资料，确认补采、无重复及旧数据不变。
5. 核对范围切换和旧标签失效；如验证账号切换，确认旧账号消息、模型配置及AI历史没有进入另一账号域。

只有完成对应环境的实测，才把该行从未验证更新为通过。接口或版本不满足时显示实际原因并导出脱敏诊断，不自动扩大权限、采集范围或改成任意账号通用模式。
