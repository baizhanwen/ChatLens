# Windows 首次使用与本机资料管理

本轮目标：新电脑从网页完成本机读取初始化，旧电脑自动复用原资料；修复大量联系人导致目录超限，并采用先搜索、再勾选确认的交互。开发验证、Windows原生与另一台电脑分别验收。

## 范围

- 正常启动不弹数据目录选择框。默认使用当前Windows用户的LocalAppData下ChatLens目录，登记文件受当前用户权限和本机身份绑定保护。
- 自动寻找已登记资料和有限位置的旧ChatLens资料，只读其配置元信息。唯一匹配当前账号时原位复用；多份或无法确认时明确导入，不取最新文件猜测、不移动或复制聊天与模型凭证。
- 新账号由当前微信程序树与文件映射元信息识别，账号不明确时不初始化。用户在网页明确开始初始化后才运行既有受限读取能力准备；密钥在本机保存，所有需要的库做HMAC验证，不输出、上传或进入公开诊断。
- 首次读取能力和会话选择分开表示。无关注范围不创建假会话或采集基线。搜索联系人／群名，手动勾选1–50个会话，最后确认才开始新文字采集。
- 每账号、每范围分别保存读取配置、消息、模型配置、AI历史与检查点。账号／范围改变后旧请求与任务结果失效。
- 联系人和表名分批读取，仅保留可选会话；搜索遍历完整已验证目录，结果分页，不把最早一页当作完整目录，也不发布不完整目录。

## 验证阶段

1. 元数据与资料管理：新目录、单份旧资料、重开复用、多份歧义、显式导入、账号不匹配、机器绑定、重解析路径、权限和单实例。
2. 初始化：当前账号识别、本人开始、进度／失败／取消、预算、所有所需库验证、失败不覆盖、空范围不得启动采集、账号改变废弃旧任务。
3. 大目录和搜索：超过10000联系人／有效表名、全局搜索、分页、搜索切换保留手选、游标失效、明确资源护栏和错误反馈。
4. 浏览器：桌面与390px首次使用、初始化中／失败、旧资料复用、搜索空白与结果、确认、账号切换以及旧Mac／Windows范围回归。
5. 交付：公开源码和历史隐私检查、离线包逐文件与固定运行时／许可核对、旧包不变、GitHub源码及新测试发行、附件下载回验。

本机合成WinAPI、SQLCipher、HTTP和浏览器验证不等于新电脑真实初始化通过；包发布后仍需在Windows实机按新用户及旧用户流程分别回测。来源库与数据保持本机，云模型调用仍由本人配置和确认范围。
