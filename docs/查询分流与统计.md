# 查询分流与本机统计

ChatLens 先在本机将问题解释成受限查询计划，再选择本机统计、模型分析、先统计再分析或澄清。计划预览会显示实际采用的日期和会话；发送时后端重新计算计划，不接受网页或模型提供的 SQL、执行代码或任意数据路径。

## 可以直接查询的内容

| 问题示例 | 处理方式 |
| --- | --- |
| 今天都谁给我发信息了／昨天有哪些人联系我 | 按日期筛选已采记录，按稳定发送人 ID 去重并计数 |
| 今天一共有多少条消息／各会话分别多少条 | 完整匹配数据计数，或按会话分组 |
| 谁最活跃／哪个会话消息最少 | 按消息数升降序排列 |
| 最新一条消息是什么／按天看消息量 | 查询最近原消息，或按上海时区的日期汇总 |
| 含“退款”的消息有几条 | 对引号内的文字作字面匹配；不把语义相似内容计入精确数量 |
| 那昨天呢／只看这个群呢 | 在当前选择范围内继承上一轮的统计维度或分析主题 |

统计通过本机 SQLite 只读、参数化查询完成，不依赖模型配置、API Key 或云端授权，不发生模型调用。人数按稳定 ID 去重，同名不同 ID 不自动合并；指定的显示名对应多个人时先澄清。总数来自全部匹配数据，和引用卡片数量分开：最多展示 50 个分组、30 条代表证据，不用 RAG 的近期样本推算总体。

引用仍可跳转到本机保存的原消息。新的消息提交后再次提问，会重新查询当前数据，不沿用旧统计结果。

## 分析与混合问题

“今天有哪些重点”“有哪些跟进线索”“分析交付进展”等问题，需要理解原文，继续使用用户在设置中配置的模型。发送前确认当前服务和本轮范围。检索执行已解析的会话、发送人、字面内容和日期条件。

分析问题在正文关键词未匹配时，可使用同一范围内受数量和长度限制的近期原文提供语境；回答会说明使用了近期片段。这不是完整语义索引，不代表读取了所有历史。相应片段仍须经过原有云端范围确认，最多 30 条、原文上下文预算约 12,000 字符。

“统计各会话消息量并分析重点”先计算本机精确总数，再将有限聚合结果和原文证据交给模型；本机数值单独显示，不让模型从证据卡数量估算总量。模型仍须提供有效引用，缺失或虚构引用的回答不作为成功答案保存。

## 时间、对象与不确定条件

- “今天、昨天、前天、本周、上周、本月、近 N 天／小时、具体日期或日期区间”会影响实际查询，而不只是正文关键词。界面与历史记录会保留绝对日期。
- 自然语言时间只能收窄页面选定的时间范围，不会自动扩大；没有交集时提示调整范围。有部分交集时明确说明只统计交集。
- 会话与发送人限定同样只能落在当前选定范围内，不能借提问读取其他账号或未选会话。不存在的名称、同名歧义及不能完整解释的时间修饰会先澄清。
- 本机精确统计只接受可以完整解释的元数据条件。“有多少客户欠款”“谁要求延期”包含语义判断，进入分析或澄清，不忽略条件后返回全部发送人数。部分片段中的发现不能当作全范围精确数量。
- 现有采集记录没有可靠的本人发送身份标记。“谁给我发消息”可列出已采消息发送者，但会明确说明无法排除本人；“我发了多少条”不会猜数。已读、未读、确定未回复及从未联系的人也不由这些记录臆造。
- 原始发送时间缺失但有采集时间的记录会明确标记采用采集时间；没有可用时间的记录单独提示无法归入日期，不假称日期完整。

所有结果仍仅覆盖选定会话在启用后已采集保存的文字。统计不是完整微信收件箱，也不会补读启用前历史。

## 验证与发布边界

单元测试使用临时数据与明确的假模型。HTTP／浏览器验收使用临时 CollectorStore 和本机合成模型，测试供应商进程通过网络审计钩子硬拒非本机连接。公开证据不包含真实正文、密钥或登录片段。

本轮没有新增第三方运行依赖；规划与统计使用 Python 标准库。Windows 打包源码的 AI 模块清单已加入规划和统计模块，历史 Windows ZIP 保留原样，没有重打新包；实际手机、Windows 新包和长期分析质量仍需分别验收。
